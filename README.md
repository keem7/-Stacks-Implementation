# Stack-Based Expression Evaluator

Module: DCOMP320 – Data Structures and Algorithm
Assignment:Stacks Implementation
Lecturer: Miss Hawa Kallon


A Python program that reads mathematical expressions from `input.txt`, evaluates
each one using **stacks**, and writes the results to `output.txt` in the same
layout as the input (separator lines are preserved).


## 1. Files

| File | Purpose |
|---|---|

| `input.txt` | Sample input used for testing (the example from the assignment brief) |
| `output.txt` | Output generated by the program for `input.txt` |
| `test_stack_evaluator.py` | Unit tests (16 tests) |
| `README.md` | This file |

## 2. Requirements

* Python 3.8 or newer. No third-party libraries are needed (standard library only).

## 3. How to run

```bash
# Default: reads input.txt, writes output.txt (both in the current folder)
python stack_evaluator.py

# Custom file names
python stack_evaluator.py my_input.txt my_output.txt

# Show the contents of both stacks after every token (good for demonstrations)
python stack_evaluator.py input.txt output.txt --trace

# Run the unit tests
python -m unittest -v
```

On some systems the command is `python3` instead of `python`.

## 4. Input file structure

* One mathematical expression per line.
* Expressions are separated by a line that contains **only** a separator,
  e.g. `-----` (three or more of the same symbol: `-`, `=`, `_`, `*`, `#`, `~`).
* Blank lines are allowed and are copied to the output unchanged.
* Spaces inside an expression are ignored.

```
3 + 5 * 2
-----
(8 / 4) + 7 * 2
-----
10 - (2 + 3) * 4
```

## 5. Output file structure

The output has the same layout as the input: each expression line is replaced by
its result, and each separator line is copied exactly as it appeared.

```
13
-----
16
-----
-10
```

If an expression is invalid, the program does **not** stop. It writes
`Error: <reason>` on that line and continues with the next expression, e.g.
`Error: Division by zero`.

## 6. How it works

Two stacks are used (Dijkstra's two-stack evaluation / shunting-yard idea):

* **Value stack** – numbers and intermediate results.
* **Operator stack** – operators and `(` markers waiting to be applied.

For every token, left to right:

1. **Number** → push onto the value stack.
2. **`(`** → push onto the operator stack.
3. **`)`** → pop and apply operators until `(` is found, then discard the `(`.
4. **`+ - * /`** → while the operator on top of the stack has the same or higher
   precedence, pop and apply it; then push the new operator.

At the end every remaining operator is applied; the single value left on the
value stack is the answer.

Precedence: unary minus (highest) → `*` and `/` → `+` and `-`. All binary
operators are evaluated left to right (so `10 - 4 - 3 = 3`).

## 7. Assumptions and limitations

* Supported operators are `+ - * /`, parentheses, and unary minus/plus
  (`-5`, `2 * -3`, `-(2 + 3)`). Exponents (`^`, `**`), functions and variables
  are not supported and are reported as errors.
* Division is true division. Whole-number answers print without a decimal point
  (`16`, not `16.0`); other answers print with up to 6 decimal places (`100 / 8 = 12.5`).
* Each expression must be on a single line.
* Division by zero, unmatched parentheses, missing operands/operators and
  unknown characters produce an `Error: ...` line instead of crashing.
* Floating-point arithmetic is used for decimals, so extremely large or very
  precise values may show normal floating-point rounding.
* **Note on the sample output in the brief:** the assignment sheet shows `17` for
  `(8 / 4) + 7 * 2`, but the correct value is `2 + 14 = 16`. The program prints
  `16`.
